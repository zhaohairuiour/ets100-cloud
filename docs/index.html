特性

六个改动点，一条链路

从模块裁剪到动画实现，全部落在可验证的代码位置上。

01

账户系统剥离

data:account 与 feature:account 两个 Gradle 模块整体删除，账户登录、绑定、头像、验证码入口全部消失。

  • settings.gradle.kts 移除 include
  • 6 个模块清理 project 依赖
02

三种本地读取下线

Shizuku / Root / 漏洞直读从激活页、引导页、首页状态与阅读页同时移除，不再申请全文件访问权限。

  • Shizuku / Sui 运行时初始化移除
  • shizuku-api 依赖删除
03

云端链路保留

ETS100AuthManager、ETS100ApiClient、作业下载与模板合并、PaperSource(Cloud) 全部保留。

  • 手机号 + 密码登录
  • 设备绑定短信验证
04

draw-phase 动画

用 Animatable + graphicsLayer 在绘制阶段直读属性，动画期间不触发重组。

  • 摒弃 animateFloatAsState 逐帧重组
  • 弹簧/补间混用做节奏
05

阶梯入场

StaggerEntrance 按 index 延迟入场，45ms 步进，上限 8 项；LazyColumn 只组合可见项，天然首屏生效。

  • 四态容器统一接入
  • 深列表不累积等待
06

过渡不裁剪

步骤切换增加 SizeTransform(clip = false)，消除高度插值导致的裁切与跳变。

  • 显式 tween 时长
  • onboarding → 主界面 alpha 淡入

FAQ

常见问题

为什么登录页变成了手机号 + 密码？

云端模式使用 ETS100AuthManager 直接调用 ETS100 登录接口（手机号 + 密码 + deviceCode），首次设备需短信验证。畅言网页登录仅作为备用入口。

为什么不再需要 Shizuku 或 Root？

三种本地读取模式已整体移除，读取路径只走官方云端 API，因此不再申请全文件访问权限，也不再初始化 Shizuku/Sui 运行时。

覆盖安装会丢数据吗？

签名证书一致，覆盖安装保留 SharedPreferences。若想重新体验引导动画，需清除应用数据，而非卸载重装。

动画为什么改成 Animatable？

animateFloatAsState 在 graphicsLayer 里读普通 Float 会导致每帧重组整棵树；改用 Animatable.value 在 draw phase 直读，动画期间零重组。

这个仓库可以公开分发吗？

原始项目声明源码闭源并禁止重新打包分发。本仓库仅作本地改造与个人备份，公开分发需先取得原始作者授权。
